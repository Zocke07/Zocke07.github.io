The Defense That Says Where It Breaks

Master's Thesis · Federated Learning Security

Federated learning keeps raw data on the device, which also means the server cannot tell a poisoned model update from an honest one. My thesis proposes L-MAD, a two-stage defense that quarantines persistent attackers and then rejects corrupted layers individually instead of throwing away the whole client along with the layers that were still learning something real. It holds 97.5% DDoS-class F₁ under a 30% poisoning attack, more than 25 points clear of the best of six reimplemented baselines, at 2.6× the speed of the nearest layer-wise method. The part I would point at first is the last chapter: twenty seeds, Wilson intervals, and a sweep designed to prove my own weakest claim wrong.

Mobile Test Automation for a Health Tracking App

Course Project · Appium · Robot Framework

A five-person suite of 103 automated test cases driving Health2Sync, a shipping Android diabetes management app, built for a software testing and verification course. I owned the settings area end to end: 15 test cases and most of the 78-keyword page library behind them. Test design came before any code: a user story, an activity diagram drawn from the outside because there was no source, then input space partitioning covered by base choice. The blood-glucose goal lands on five blocks, three valid ranges and two invalid ones, so a rejected input gets verified as deliberately as an accepted one. The hard part was a stateful app with no reset hook, where cleanup is something every test has to pay for itself.

Sky Scraper Escape

C++ · MFC · Object-Oriented Design

Fly a plane through a city skyline across seven levels, each adding a twist: narrowed vision, flickering obstacles, buildings that move vertically, gravity that inverts. Built for an OOP lab course on top of a teaching game framework that allows exactly three states. The design is the interesting part. I mirrored the framework's own state interface onto a level base class, so every level and the menu became interchangeable objects behind one pointer, and the main loop forwards events without knowing which one it is talking to. I wrote most of the team's game code: the player, that base class, and the menu and level-select screens.

Test Automation Best Practices: A Case Study Analysis

Capstone Project · Industry-Academia Research

My graduation capstone, written from inside the Sunbird co-op with two teammates. It documents how a commercial test automation team actually works: test steps designed by hand and confirmed with the product manager before any code is written, mob programming sessions, a CI gate of ten runs plus five throttled, and pull requests that close only when the company's engineers approve. It also analyzes four years of the team's test-case statistics to explain why output declined. Because the real code stays behind the NDA, I built the exhibit from scratch: a small web app and Robot Framework suites walking the same requirement-to-review pipeline on a target I could publish.
